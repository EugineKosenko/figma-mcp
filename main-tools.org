#+title: Реєстр інструментів

Кожен інструмент реалізовано в окремому самодостатньому org-файлі зі своїм ~run~ (див. [[file:main-tool-outline.org][~outline~]],
[[file:main-tool-texts.org][~texts~]], [[file:main-tool-comments.org][~comments~]]). Оскільки noweb-посилання не резолвяться між org-файлами, спільні для всіх
інструментів частини — оголошення підмодуля, опис для ~tools/list~ і диспетчеризація виклику за назвою —
зведені тут, в одному файлі.

Усі інструменти читають дані з =Figma= лише текстом: скриншоти до реєстру не входять, бо всі дані,
потрібні для аналізу макетів, є в текстових шарах і структурі вузлів.

* Спільні аргументи

Усі інструменти приймають необов'язкові ~file~ і ~refresh~. ~file~ — ключ файлу або повна адреса файлу з
браузера (ключ береться із сегмента після ~/design/~, ~/file/~ чи ~/board/~). Без нього береться
~FIGMA_FILE~, а якщо не задано й його, інструмент повертає зрозумілу помилку, а не падає. ~refresh~
пропускає кеш і питає =Figma= наново. Інструменти для вузлів приймають ще обов'язковий перелік ~ids~
(масив або рядок через кому); id із адреси браузера має дефісну форму (~979-3~) і перетворюється на форму
=api= (~979:3~).

Ключ файлу з адреси: адреса має вигляд ~https://www.figma.com/design/ключ/назва?node-id=979-3~, тож
беремо сегмент одразу після маркера й обрізаємо його на першій скісній рисці, знаку питання чи решітці.

#+begin_src rust :noweb-ref Визначення
  fn key_from(file: &str) -> String {
      for marker in ["/design/", "/file/", "/board/"] {
          if let Some((_, rest)) = file.split_once(marker) {
              return rest.split(|c| c == '/' || c == '?' || c == '#').next().unwrap().to_string();
          }
      }

      file.to_string()
  }

  pub fn file_key(arguments: &serde_json::Value) -> Result<String, String> {
      match arguments["file"].as_str() {
          Some(file) => Ok(key_from(file)),
          None => std::env::var("FIGMA_FILE")
              .ok()
              .filter(|file| !file.is_empty())
              .map(|file| key_from(&file))
              .ok_or("Не вказано файл: передайте аргумент file (ключ або адресу файлу) чи задайте змінну FIGMA_FILE.".to_string()),
      }
  }
#+end_src

Дефісну форму перетворюємо лише тоді, коли обидві половини складаються з цифр: складніші id (наприклад,
вузли всередині екземплярів компонентів на кшталт ~I5:1;2:3~) лишаються як є.

#+begin_src rust :noweb-ref Визначення
  pub fn node_id(id: &str) -> String {
      match id.split_once('-') {
          Some((left, right))
              if !left.is_empty()
                  && !right.is_empty()
                  && left.bytes().all(|b| b.is_ascii_digit())
                  && right.bytes().all(|b| b.is_ascii_digit()) =>
              format!("{}:{}", left, right),
          _ => id.to_string(),
      }
  }

  pub fn node_ids(arguments: &serde_json::Value) -> Result<Vec<String>, String> {
      let ids: Vec<String> = match &arguments["ids"] {
          serde_json::Value::Array(items) => items.iter().filter_map(|id| id.as_str()).map(node_id).collect(),
          serde_json::Value::String(text) => text.split(',').map(|id| node_id(id.trim())).collect(),
          _ => Vec::new(),
      };

      if ids.is_empty() {
          return Err("Не вказано ids: передайте перелік id вузлів, напр. [\"979:3\"].".to_string());
      }

      Ok(ids)
  }

  pub fn file_and_ids(arguments: &serde_json::Value) -> Result<(String, Vec<String>), String> {
      Ok((file_key(arguments)?, node_ids(arguments)?))
  }

  pub fn refresh(arguments: &serde_json::Value) -> bool {
      arguments["refresh"].as_bool().unwrap_or(false)
  }
#+end_src

* Відповідь інструмента

Успіх і невдача передаються однаково — текстом, а ознака ~isError~ каже клієнтові, що саме це. Причина
невдачі (вичерпаний ліміт, ~403~) так доходить до моделі, а не губиться.

#+begin_src rust :noweb-ref Визначення
  pub fn reply(result: Result<String, String>) -> serde_json::Value {
      match result {
          Ok(text) => serde_json::json!({ "content": [{ "type": "text", "text": text }], "isError": false }),
          Err(text) => serde_json::json!({ "content": [{ "type": "text", "text": text }], "isError": true }),
      }
  }
#+end_src

* Перевірки

Розбір адреси й id не потребує мережі, тож перевіряється звичайними тестами. Змінну ~FIGMA_FILE~ тести не
чіпають: змінні середовища спільні для всіх тестів, що йдуть паралельно.

#+begin_src rust :noweb-ref Тести
  #[test]
  fn key_from_address() {
      assert_eq!(key_from("https://www.figma.com/design/LismtgSCxfd7p8igMtYct3/Internal-Interfaces?node-id=979-3&t=abc"), "LismtgSCxfd7p8igMtYct3");
      assert_eq!(key_from("https://www.figma.com/file/AbC123/Name"), "AbC123");
      assert_eq!(key_from("https://www.figma.com/design/AbC123?node-id=1-2"), "AbC123");
      assert_eq!(key_from("AbC123"), "AbC123");
  }

  #[test]
  fn file_from_argument() {
      assert_eq!(file_key(&serde_json::json!({ "file": "https://www.figma.com/design/AbC123/N" })).unwrap(), "AbC123");
  }

  #[test]
  fn node_id_dash_form() {
      assert_eq!(node_id("979-3"), "979:3");
      assert_eq!(node_id("979:3"), "979:3");
      assert_eq!(node_id("I5:1;2:3"), "I5:1;2:3");
      assert_eq!(node_id("abc-1"), "abc-1");
  }

  #[test]
  fn node_ids_forms() {
      assert_eq!(node_ids(&serde_json::json!({ "ids": ["979-3", "980:310"] })).unwrap(), vec!["979:3", "980:310"]);
      assert_eq!(node_ids(&serde_json::json!({ "ids": "979-3, 980-310" })).unwrap(), vec!["979:3", "980:310"]);
      assert!(node_ids(&serde_json::json!({})).is_err());
      assert!(node_ids(&serde_json::json!({ "ids": [] })).is_err());
  }
#+end_src
